# Supporting research and design

<!-- @ref:docs-research; @tag:documentation -->
<!-- @link:docs-index; @link:paper-development; @link:doc-evidence. -->

These documents retain research proposals, literature background and design
intent. They are separate from [review records](../audits/readme.md) and the
[current software guides](../readme.md). A plan's description of a future model
or interface is not a claim that the code implements it. The
[paper](../../paper/downstream.tex) explains the implemented mathematics;
the [task board](../../tasks/README.md) tracks actionable work and acceptance.

| Material | Purpose |
| --- | --- |
| [Life-course research plan](life_course_research_plan.md) | Scientific direction and milestone dependencies. |
| [Causal graph design](causal_graph_plan.md) | Proposed model records, compatibility and future composition. |
| [Probabilistic roadmap](probabilistic_roadmap.md) | Implemented machinery contrasted with evidence-gated future methods. |
| [Related work](prior_attempts.md) | Background on simulation and causal-model precedents. |
| [Literature acquisition plan](literature_acquisition_plan.md) | Corpus goals and acquisition process. |
| [Extraction register](queued_extractions.md) | Source-row status; remains the single extraction table, coordinated through tasks. |
| [Evaluation protocol](scenario_evidence_protocol.md) | Dated selection and independent-event requirements, with recorded amendments. |
| [Website experience plan](website_experience_plan.md) | Proposed public journey and comprehension research. |
| [Rendering design](rendering.md) | Explanation layers and visual/language intent beyond the current browser app. |

Keep scope and proposed-versus-implemented status explicit when changing a
plan. Put new mathematics explaining implemented behavior in the paper, and
new operational instructions in the appropriate software guide. Do not copy
these milestone lists into another backlog.
